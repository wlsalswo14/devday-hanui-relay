# 대화와 작업 에이전트

서비스의 메인과 작업 에이전트 모두 `gemma-4-26b-a4b-it`를 사용합니다. 별도 인스턴스지만 같은 로컬 인증 설정과 추론 수준을 사용합니다. 개발용 Codex 서브에이전트와는 다릅니다.

메인은 현재 메시지와 같은 세션의 최근 대화·저장된 기억을 받아 짧은 답변 또는 작업 위임을 결정합니다. 이름·선호·주제를 이어받고 “그것”, “두 번째” 같은 후속 질문을 앞선 대화에서 해석합니다. 최근 최대 24개 메시지를 약 18,000자 예산으로 전달하며 원문 인용·해석과 검색 결과의 요약도 포함합니다. 저장된 기억은 최근 20개를 전달합니다. 전체 기록은 SQLite에 보존하지만 모든 과거 대화를 무제한으로 모델에 보내지는 않습니다. 다른 세션은 섞지 않습니다. 인사·감사·일반 대화에는 DB 검색어 생성, 고문헌 인용, 생활기록 저장을 강제하지 않습니다.

작업이 필요하면 별도 Gemma 인스턴스가 정해진 역할 프롬프트로 처리합니다.

브라우저의 다른 탭으로 전환하거나 앱의 기록·자료·캘린더·리포트 화면으로 이동해도 진행 중인 대화 응답은 계속 처리되고 같은 세션에 저장됩니다. 화면이 숨겨지는 `visibilitychange`는 취소 사유가 아닙니다. 응답 중에는 새 대화 생성·다른 대화 선택을 잠시 막으며 현재 대화 삭제는 허용합니다. 삭제 확인 후 실행 중인 응답을 취소하고, 서버가 취소 처리 중이면 최대 2.5초 동안 삭제를 재시도합니다. 명시적인 중단 버튼과 페이지 종료·이탈(`pagehide`, 새로고침 포함)은 응답을 취소하며 취소된 응답은 저장하지 않습니다. 이미 저장된 대화는 탭을 닫아도 남고 대화 삭제 시 제거됩니다.

- `literature`: 최근 대화·한의사 지침을 참고해 검색어를 만들고 DB를 검색합니다. 원문과 국역을 원본 DB와 대조하며, 인용 문자열 및 한국어 해석 필드를 검증합니다.
- `records`: 사용자 발언을 정리하고 생활기록·체크인·목표 초안을 제안합니다. DB·웹 검색과 고문헌 인용을 하지 않습니다.
- `records_read`: 기존 기록을 조회해 답변만 작성하며 관찰·일정 변경을 하지 않습니다.
- `calendar`: 현재 대화의 일정·예약 준비 자료를 보고 변경 요청을 구조화합니다. DB·웹 검색과 고문헌 인용을 하지 않습니다.
- `web`: 명시적인 웹·구글·네이버 검색 요청, 최신 공개 정보·뉴스·가격·운영 시간·실제 장소 정보에 선택합니다. 메인이 이 역할을 선택하면 검색어 에이전트에 `SEARCH_REQUIRED=true`를 전달하고 검색어를 만든 뒤 실제 네이버·구글 검색을 실행합니다. 검색어 단계의 두 번째 판단이 웹 작업을 조용히 취소하지 않습니다. 앞선 주제는 작업 설명과 최근 대화로 전달합니다. 검색을 금지한 요청과 앱의 검색 동작에 관한 질문에는 웹 역할을 선택하지 않도록 지시합니다. 고문헌 검색을 강제하지 않습니다.

메인은 작업 에이전트가 준비한 짧은 설명을 검증 후 그대로 전달합니다. 결과를 다시 작성하는 메인 호출은 하지 않습니다. 원문 인용·위치도 에이전트의 검증된 결과를 그대로 표시합니다. 일반 작업은 메인 판단 → 작업 에이전트의 두 번 호출이고, 문헌 작업은 검색어 생성 호출이 추가되어 통상 세 번 호출합니다. 실제 도구 필요에 따라 추가 호출이 생길 수 있습니다. 작업 프롬프트도 공통 대화 프롬프트를 재사용하지 않고 간결한 전용 프롬프트를 사용합니다.

작업별 출력 형식을 최소화합니다. 문헌은 설명·인용만, 캘린더는 설명·일정 작업만 생성합니다. 기록은 기억·관찰·기록 작업을 생성하되 같은 수치 정보를 기억·관찰·체크인에 중복 생성하지 않도록 지시합니다. 사용하지 않는 빈 일정 필드를 출력하지 않아도 됩니다. 서버가 기존 UI 형식으로 정규화하며, 문헌 출처 ID는 검증된 인용에서 복원합니다. 인용 대조와 일정 변경에 필요한 실제 사용자 발언 검증은 생략하지 않습니다.

일정 변경과 환자 기록 저장은 서버의 기존 검증 및 트랜잭션을 통해 실행합니다. 작업 프롬프트가 원래 사용자 발언을 대신해 쓰기를 허가하지 않습니다. 취소·인용 오류·에이전트 답변 오류 시 작업 결과를 저장하지 않습니다. 사용자 확인이 필요한 체크인·목표는 기존 초안 흐름을 유지합니다. 한 번의 위임은 한 역할로 제한합니다.

웹 검색 실패·모델 한도는 기존 오류 처리로 표시합니다. 별도 작업 에이전트의 호출도 같은 API 할당량을 사용합니다. 예약은 로컬 방문 준비이며 외부 병원의 확정을 대신하지 않습니다.
