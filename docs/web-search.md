# 웹검색

메인 Gemma가 같은 세션의 대화를 참고해 웹 작업을 선택하면 별도 Gemma 에이전트가 공개 검색어를 정하고 실제 검색을 실행한다. 웹 역할에서는 검색어 단계에 `SEARCH_REQUIRED=true`를 전달해 두 번째 검색 필요 판단으로 실행을 건너뛰지 않는다. 네이버 공개 검색 페이지와 Google Playwright 검색을 동시에 호출하고 관찰 결과를 에이전트에 전달한다. 같은 URL은 하나로 합치고 검색엔진 표기는 모두 유지한다. 별도 검색 API 키나 화면에 보이는 브라우저 창은 필요하지 않다. 검색 결과 페이지의 요약을 사용하며 링크 대상의 본문 전체를 읽었다고 주장하지 않는다.

검색 결과의 실제 서비스명과 검색엔진별 성공·실패 상태를 응답에 표시하고, 출처 3개를 먼저 보여주며 나머지는 펼쳐볼 수 있다. 네이버에서는 광고·로그인·내부 주소·검색 메뉴를 제외하며 병합 결과는 공개 링크만 받는다. 한쪽이 실패해도 다른 쪽 결과는 유지하며, 모두 실패하거나 검증 가능한 링크가 없으면 성공으로 처리하지 않는다. 요청을 취소하면 진행 중인 검색 자식 프로세스를 종료하고 결과를 버린다. 개인 기록·의사 지침을 검색어로 보내지 않도록 에이전트에 지시한다.

2026-10-10: Google 자동 검색은 `/sorry/index` CAPTCHA로 차단되는 것을 확인했다. Google 도움말은 자동화 트래픽이나 공유 네트워크의 트래픽이 원인일 수 있다고 설명하지만 이 PC에 적용된 내부 판정 이유는 확인할 수 없다. CAPTCHA 우회를 추가하지 않았다. 차단 시 서버 프로세스 내에서 Google 재시도를 5분간 보류하고 네이버 결과를 유지한다. 제한 상태는 UI에 표시하고 제한된 엔진을 사용했다고 주장하지 않는다. 명시적인 브라우저 조작 기능은 기존 Playwright MCP를 유지한다.

네이버 단독 단계에서는 임시 환자 DB와 실제 Gemma·Chromium 화면에서 “질병관리청 수면 건강 안내”와 “서울 강남역 한의원” 질문의 검색→답변→출처 링크 표시를 확인했고 각각 9.58초와 9.86초였다. 두 엔진 연결 후 실제 검색 도구 호출은 10.43초였으며 네이버 8건, Google 차단 상태를 반환했다. 이는 추론 시간까지 포함한 측정이 아니다. 두 엔진이 모두 성공하는 화면은 고정 응답 대역으로 검증했으며 Google의 실제 검색 성공은 확인하지 못했다. 소수의 실측이며 보장 시간이 아니다. 검색 결과의 모든 사실·병원 운영 정보가 확인된다는 의미는 아니다. 공개 검색 페이지 구조나 접근 정책 변경 시 파서 보완이 필요할 수 있다.

Google 안내: https://support.google.com/websearch/answer/86640

검증: 자동 테스트 153개 통과. 두 엔진 중복 제거·출처 병합, 한쪽 실패 시 다른 결과 유지, 모두 실패, 차단 재시도 보류를 검증했다. `python -X utf8 ui_dual_search_smoke.py`는 두 엔진 성공 및 Google 차단 화면·출처 펼치기·모바일 레이아웃을 고정 응답으로 검증한다.
