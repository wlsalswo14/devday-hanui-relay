# 실제 로컬 앱 Playwright 확인 · 2026-10-11

`http://127.0.0.1:8765`에 설치된 Chrome을 Playwright로 연결했다. 대화·관리 시작·캘린더·문헌 검색은 실제 Google-hosted Gemma `gemma-4-26b-a4b-it` / minimal 호출로 확인했다. 개인 데이터 대신 임시 프로필·대화·일정을 만들었으며 종료 후 삭제하고 기존 프로필을 복원했다. 각 항목은 독립 실행에서 확인된 결과를 합산한 것으로, 전체 시나리오가 단일 실행에서 모두 통과한 것은 아니다.

## 확인한 동작

- 시스템 지침 화면에서 건강 프로필 저장 → 새 대화에서도 별명·알레르기 참조.
- 같은 대화의 후속 질문에 앞선 내용 반영. 캘린더 이동 후 돌아오기·새로고침에서도 대화 유지.
- 인사만 보낼 때 검색 출처·도구 작업 없이 답변.
- 관리 시작 → 실제 에이전트의 첫 질문 → ‘아니요’ 기록 → 목표 자기보고 0%.
- 7일 중 기록이 없는 6일을 ‘기록 없음’으로 표시. 근거 링크로 실제 사용자 발언·날짜 확인.
- 주간 기록을 리포트로 가져오기, 직접 편집·저장·새로고침 후 유지.
- 수동 일정 저장·ICS 내보내기. 실제 캘린더 에이전트가 요청한 2026-10-13 15:00~15:10 일정 저장, 저장 결과 표시·ICS 반영.
- 실제 고문헌 검색에서 원문 인용, 검증된 본문 시작·종료 위치, 한국어 풀이 반환.
- 1440·390·320px에서 대화·프로필 대화상자·캘린더·리포트 확인. 가로 넘침과 JavaScript pageerror 없음.

## 발견하고 수정한 문제

캘린더 에이전트가 `operation`을 빠뜨린 일정 초안을 보내면 서버가 이를 건너뛰고 ‘등록할게요’라는 답변만 저장했다. 날짜·제목 누락도 실제 호출에서 관찰됐다.

- 캘린더 출력에 작업 종류·제목·시작·종료·대상 ID·현재 요청 근거를 필수로 지정했다.
- 서버는 모든 일정·예약 변경 초안을 검증한다. 작업 종류 없는 변경은 성공처럼 대화에 남지 않는다.
- 불완전한 캘린더 초안은 저장 전에 같은 작업 에이전트에 한 번만 다시 요청한다. 사용자 요청과 기존 대화가 근거이며, 빠진 정보를 임의로 채우지 않는다.
- 잘못된 JSON 응답은 기록 변경 전에 동일 요청으로 한 번 재시도한다. 계속 실패하면 오류를 표시한다.
- 누락 작업 거부, 초안 재요청 후 단 한 번 저장, JSON 재시도 상한을 회귀 테스트로 추가했다.

수정 후 테스트 181개 통과. 실제 캘린더 생성은 9.23초, 고문헌 인용·해석은 10.68초에 확인됐다. 일반 대화는 약 2~6초였으나 프로필 참조 한 건은 22.61초 걸렸다. 이 수치는 소량의 수동 검증 측정값이며 성능 보장이 아니다.

## 남은 검증·한계

실제 공급자 HTTP 500, 잘못된 JSON, 추가 문헌 요청의 180초 응답 대기가 관찰됐다. 따라서 실제 AI 연결 전체를 안정적이라고 판정하지 않는다. 대기 요청의 브라우저 종료 후 서버가 다시 요청을 받을 수 있고 임시 대화를 삭제할 수 있음을 확인했다.

출처 상세창의 실제 클릭 검사와 실제 리포트 자동 정리·적용 검사는 마지막 AI 호출 지연으로 완료하지 못했다. 고문헌 원문·위치·해석 반환 및 리포트 수동 저장은 별도로 확인했다. Google 로그인은 사용자 요청에 따라 비활성 상태다. 실제 OS 푸시 수신·외부 병원 예약 접수는 이번 검증에 포함하지 않았다.

화면 캡처·실행별 JSON 결과는 커밋하지 않는 `.runtime/screenshots/live-check/`에 보관했다.
