# Hanui Relay

일상을 이야기하면 생활 맥락을 기억하고, 한의학 정보를 찾아보고, 생활 관리와 병원 방문 준비까지 이어가는 로컬 데모.

**개인 관리 추가:** 시스템 지침의 텍스트 건강 프로필을 필요한 부분만 검색해 대화 메모리로 사용한다. 관리 시작, 오늘의 예/아니요 확인, 여러 대화의 주간 기록·근거, 수면·카페인 추이, 리포트 가져오기와 방문 후 지침 연결을 지원한다. Web Push는 서버가 실행 중이면 앱을 닫아도 전송할 수 있다. Google 계정 연결은 현재 보류하며 설정 없이 로컬에서 사용할 수 있다. 사용법·구현 범위·검증은 [개인 건강 관리 안내](docs/HEALTH_PLATFORM.md)를 참고한다.

시연의 중심은 **한의사 진단·생활 지침 → Hanui의 첫 확인 질문 → 환자 답변과 코칭 → 고문헌 DB 탐색·한국어 해석 → 근거가 붙은 내원 리포트 → 병원 방문 준비**다. 의료진이 입력한 진단·평가를 대화의 맥락으로 사용하며 AI가 새 진단을 내리지 않는다.

## 구현된 흐름

| 기능 | 실제 동작 |
|---|---|
| 지속 대화 | Google Gemini API의 **Gemma 4 26B A4B / minimal** 호출. 이전 대화·자기보고 생활기록·체크인·목표·일정을 함께 참고한다. |
| 여러 대화 | 새 대화 생성, 목록 전환, 이름 변경, 최근 활동순 목록과 재접속 복원. 첫 메시지로 자동 제목을 만들고 대화별 생활기록·일정·작성 중 메시지를 분리한다. 현재 대화를 삭제하면 다른 대화로 이동한다. |
| 기록·자료 사이드바 | 처음에는 접힌 상태로 대화를 넓게 보여준다. 생활기록과 찾아본 자료는 오른쪽 패널을 열어 확인하며 열림·닫힘 상태를 기억한다. 모바일에서는 펼쳐지는 패널로 표시한다. |
| 한의학 DB | 현대 자료 요약 **42건** + 고문헌 원문 **57건**, 총 **99건**을 SQLite에 가져온다. 에이전트가 질문·앞선 대화에서 키워드를 정하면 원문·한국어 독해·항목을 전문 탐색하고 관련 문장을 정리한다. |
| 원문 인용·한국어 해석 | 고문헌의 정확한 한자 인용에 에이전트가 짧은 한국어 해석을 붙인다. 해석을 먼저 보여주고 문헌명·장절·단락·본문 문자 위치·판본 원문 링크는 펼쳐 확인한다. 인용은 DB 본문과 대조하고 해석은 별도로 저장한다. |
| 생활 기록 | 수면·식사·활동·카페인·스트레스·불편감·목표에 관한 자기보고 발언을 원문과 연결해 기억한다. 항목 삭제와 전체 기록 내보내기가 가능하다. |
| 매일 관리 | 날짜별 체크인 저장·수정·삭제, 최근 7일 평균과 수면 그래프, 생활 목표와 일별 완료 기록. 대화의 수치 기록을 체크인 초안으로 제안하며 사용자가 확인 후 저장한다. |
| 한의사 지침 코칭 | 진단·평가와 생활 지침을 입력하면 에이전트가 먼저 쉬운 확인 질문을 건넨다. 환자가 답하면 원문·날짜·수치를 대조해 기록하고 지침과 비교한 코칭 및 다음 질문을 보여준다. 의료진 입력과 환자 자기보고를 분리하며 질문 자체를 실천 기록으로 저장하지 않는다. |
| 자유 작성 리포트 | 직접 작성하거나 ‘에이전트 정리’로 Gemma 4가 작성 중인 글·대화·생활 기록·의료진 지침을 정리한 초안을 만든다. 형식과 목적은 자유롭게 요청할 수 있으며 원문 인용을 대조하고 날짜·근거를 붙인다. 미리보기에서 편집기에 적용한 후 직접 수정·저장한다. 대화별 SQLite 저장, Ctrl/Cmd+S, 인쇄·PDF를 지원한다. |
| 병원 카드 | 에이전트의 **Google Search**으로 실제 병원을 찾고 이름·주소·공개 자료에 근거한 추천 이유를 표시한다. 전화·확인된 예약 링크·정보 원문을 제공하고, 확인한 후기 자료는 접어서 표시한다. |
| 예약 관리 | 에이전트가 대화에서 병원 선택과 희망 시간을 받아 예약 준비를 저장·변경·취소한다. 사용자가 병원에서 확정받았다고 보고하면 방문 일정을 생성한다. 전화·확인된 예약 링크도 유지한다. |
| 자체 캘린더 | 앱 안의 월별 달력·날짜별 일정·예약 상태 표시. 에이전트에게 일정 추가·수정·삭제를 직접 요청할 수 있고 달력 화면의 대화 입력에서도 동작한다. 날짜·시간·대상이 모호하면 먼저 질문한다. 수동 관리와 `.ics` 내보내기도 지원한다. |
| 현대 웹 자료 | 대화에서 에이전트가 검색어를 정하고 실제 Google Search을 수행한다. 결과·출처는 같은 대화에 표시하고 검색 기록을 저장한다. 별도 웹·병원 검색 메뉴는 없다. |

**예약 준비는 병원에 접수된 상태가 아니다.** 실제 접수와 변경·취소는 병원 전화·예약 페이지에서 완료한다. 에이전트가 관리하는 것은 앱의 예약 준비·확정 보고·취소 기록이다. 확정된 방문의 희망 시간을 바꾸면 준비 상태로 돌아가며 병원에서 다시 확인받아야 한다. 자체 캘린더는 외부 캘린더 계정 연결 없이 동작한다.

대화 예: “내일 오후 3시에 산책 30분 넣어줘” → “그 산책을 오후 4시로 옮겨줘” → “그 일정 삭제해줘”. 검색된 병원을 선택한 뒤 “이 병원으로 내일 오후 2시 예약 준비해줘”라고 요청할 수 있다. 이전 대화의 완료 버튼은 캘린더를 열기만 하며 변경을 재실행하지 않는다.

카드의 ‘방문 일정 저장’은 개인 일정이다. 병원에서 받은 예약 확정은 별도로 기록한다. 지도·경로·위치 조회·이동 시간 추정은 제공하지 않으며 지도 API 키나 SDK 설정이 필요하지 않다.

## 실행

앱을 열어 두면 현재 대화에 저장한 일정의 **시작 30분 전**부터 에이전트 리마인드가
자동으로 표시된다. Gemma 4가 알림 문구를 만들며 제목·시간은 저장한 일정 그대로 표시한다.
알림을 닫으면 새로고침해도 다시 표시하지 않는다. 일정 변경·삭제 시 이전 알림은 무효가 된다.
이 기본 앱 내 알림과 별도로, 대화 위 **알림**에서 Web Push를 켜면 서버 실행 중에는 탭을 닫아도 알림을 전송할 수 있다. 문자 알림은 제공하지 않는다. 미접수 예약 준비는 확정 일정으로
알리지 않는다. 알림은 대화별로 분리하며 현재 열어 둔 대화의 캘린더만 확인한다.

### 백그라운드 웹검색 (2026-10-10)

`start.ps1`은 별도의 **headless Playwright MCP**를 localhost:8932에서 시작한다.
Node.js/npm과 Google Chrome이 필요하며 확장 프로그램 토큰은 사용하지 않는다.
사용자의 브라우저 창이나 탭을 조작하지 않는다. Gemma가 질문의 검색 필요 여부를
판단하고, 필요할 때만 직접 정한 공개 검색어로 Google 검색 결과를 읽는다.
단순 대화·생활 기록·지침 코칭·고문헌 질문은 DB로 답할 수 있으며, 최신 정보나
외부 근거가 필요하다고 판단하면 검색 결과와 검증된 고문헌 인용을 함께 참고한다.
전체 환자 기록이나 의료진 지침은 Google 검색창에 전송하지 않는다.
확인한 검색 링크는 대화의 참고 자료에 저장한다. 검색 스니펫을 읽는 기능이며
링크된 모든 페이지 전문을 읽었다고 표시하지 않는다.

현재 실제 headless 검증에서는 Google이 HTTP 429/로봇 확인을 반환했다.
이 경우 검색 성공이나 출처를 만들어내지 않고, **검색 실패 표시 + DB 기반 답변**을 제공한다.
CAPTCHA를 자동으로 우회하지 않는다. 기존 Gemini API의 Google Search grounding 경로와
별개이며, 대화의 기본 웹검색 경로는 이 Playwright 방식이다.
`HANUI_BROWSER_SEARCH=0`으로 자동 검색을 끌 수 있다.
직접 실행할 때는 먼저 `python start_browser_search.py`, 이어서 `python server.py --port 8765`를 실행한다.
`HANUI_BROWSER_MCP_URL`은 loopback HTTP MCP 주소만 허용한다.

Python 3.11 이상. 서버·DB·자료 다운로드에는 Python 표준 라이브러리만 사용한다.

Google 로그인과 Web Push를 사용하려면 `python -m pip install -r requirements.txt`로 추가 모듈을 설치한다. Google 연결은 OAuth 설정 전까지 비활성화되며, 로컬 대화는 계속 사용할 수 있다.

```powershell
python server.py --port 8765
```

<http://127.0.0.1:8765>를 연다. `start.ps1`로도 시작할 수 있다. 로컬 loopback 전용으로, 공개 배포용 로그인·사용자 권한은 포함하지 않는다.

현재 서비스 에이전트는 Google Gemini API의 `gemma-4-26b-a4b-it` 모델을 사용한다. 대화 지연을 줄이기 위해 기본 사고 모드는 `minimal`이며 `HANUI_GEMMA_THINKING=high`로 변경할 수 있다. 다른 모델로 자동 전환하지 않는다. DB 전체를 검색한 뒤 상위 자료 4건을 모델에 전달하고 인용은 전체 원문과 대조한다. 개발 도구 Codex와 서비스의 응답 모델은 별개다. 해커톤 제출 당시의 OpenAI 구현은 Git 체크포인트에 보존되어 있다.

```powershell
$env:HANUI_GOOGLE_API_KEY = '<Google API key>'
python server.py --port 8765
```

Windows에서는 현재 사용자 계정에 묶인 DPAPI 암호화 키 파일 `.runtime/google-key.dpapi`도 지원한다. 키는 브라우저에 전달하거나 Git에 저장하지 않는다. 런타임은 선택한 키 하나를 사용하며 요청 한도 오류를 다른 계정의 키로 우회하지 않는다. 429·5xx 오류는 화면에 표시하며 실패한 대화에서는 기록과 일정을 변경하지 않는다.

응답 중 탭을 숨기거나 닫고, 화면·대화를 전환하거나 새로고침하면 요청을 취소한다. ‘응답 중단’으로도 취소할 수 있다. 서버는 Google HTTP 연결을 담당하는 별도 프로세스를 종료하고 대기 상태를 해제한다. 취소된 응답·생활기록·일정은 저장하지 않으며 늦게 돌아온 결과도 버린다.

질문 분석과 DB 답변은 웹 검색 없이 실행한다. 에이전트가 고른 키워드로 서버가 SQLite 전문을 탐색한 뒤 원문과 해당 대화 상태를 모델에 제공한다. 원문 인용·한국어 해석·환자 발언·일정 변경의 검증은 기존 장치를 공유한다. 공개 정보 탐색에는 Gemma의 Google Search 도구를 사용하고 실제 검색 메타데이터와 출처가 없는 결과는 표시하지 않는다. `codex_bridge.py`의 기존 OpenAI 어댑터는 제출 당시 구현을 보존하며 현재 기본 실행에서는 호출하지 않는다.

## DB와 자료

SQLite 파일은 `.runtime/hanui.sqlite3`다. 서버 시작 시 `data/knowledge.seed.json`과 `data/classics.seed.json`을 검증·가져오고, 자료 파일이 바뀌면 검색 시 갱신한다. 대화, 인용 원문과 위치, 발언과 연결된 기억, 체크인, 목표, 병원 검색, 예약 준비, 일정은 실제 DB에 저장되어 재접속 후 복원된다. 전체 세션 삭제 시 연결된 모든 기록이 삭제된다.

현대 자료 42건은 한국한의약진흥원·BioIN·KCI·NIH NCCIH의 공개 자료를 확인한 자체 요약이다. 약재 기원 목록의 33종은 원료 정보다. 고문헌은 공개 Wikisource 원문을 판본에 고정하여 별도 저장한다. 수록 범위와 이용·출처 정보는 [고문헌 자료](docs/CLASSICAL_SOURCES.md)에 기록한다. 고대의 기록과 현대 임상 근거를 구분한다.

전문 검색은 연결된 KMM 전문 색인과 앱의 소량 시드 자료를 탐색한다. 한국어·한문 키워드를 에이전트가 고르고 대화에는 최대 4개 항목을 제공한다. 수록한 원문 범위의 전문 탐색이며 한의학 고문헌 전체를 보유하는 DB는 아니다.

같은 세션에서는 최근 대화·저장된 기억을 참고해 챗봇처럼 대화를 이어간다. **고문헌 탐색 역할의 답변은 원문 인용·한국어 해석을 필수로 포함**한다. 인사·일상 대화·생활기록·일정 작업에는 고문헌 탐색을 강제하지 않는다. 서버가 원문 문자열·문자 위치·한글 해석을 확인하며 문헌 탐색에서 관련 자료를 못 찾거나 인용 검증에 실패하면 해당 답변을 보류한다. 원문 일치 검증이 번역의 의미나 임상적 타당성을 보증하지는 않는다. 명시적인 웹검색 요청과 최신 공개 정보 질문은 별도 작업 에이전트가 네이버·구글을 검색하고 출처와 검색엔진별 상태를 표시한다.

자료 원문 다운로드와 재생성:

```powershell
python refresh_data.py
python refresh_classics.py
```

공식 URL만 내려받는다. 기원 목록 PDF는 확인한 SHA256과 일치해야 하며 자료가 변경되면 재검토를 요구한다. 다운로드 실패 시 기존 seed를 유지한다. 원문 PDF·HTML은 `data/source-documents/`에 로컬 참조용으로 보관하고 Git에서 제외한다. 공개할 출처·수집·해시 정보는 `data/sources.manifest.json`에 기록한다.

## 개인정보와 한계

AI 대화와 정보 검색은 별도 동의창 없이 대화에서 실행한다. 대화·생활기록·체크인·일정 등은 현재 계정의 OpenAI 모델에 전달된다. 체크인·목표 초안은 검토 후 저장한다. 사용자가 현재 대화에서 명시한 캘린더·예약 기록 요청은 에이전트가 직접 반영하고 실제 처리 결과를 보여준다. 가정·금지·불명확한 대상은 변경하지 않는다. 병원 확정 기록에는 실제 확정을 받았다는 사용자의 보고가 필요하다.

대화·DB·임시 모델 파일·개인 기록 내보내기는 `.runtime/`에 두며 Git에서 제외한다. `.ics`와 JSON 내보내기에는 사용자의 메모가 포함된다. ICS에서 예약 준비는 `TENTATIVE`로 표시하며 취소 기록은 제외한다. SQLite 자체 암호화와 공개 서비스 인증은 없다.

미병·질병·체질의 개인 진단, 증상에 맞춘 약재·처방·복용량 추천, 약재 구매는 제공하지 않는다. 출처 ID·JSON 형식·기억 인용을 검사하지만 의학적 문장의 의미를 임상적으로 보증하는 검증은 아니다. 공개 후기의 접근성과 정확성은 사이트와 검색 결과에 따라 다르며 후기 자체가 진료 역량을 증명하지 않는다.

## 검증

```powershell
python -m unittest discover -s tests -v
python ui_smoke.py
python ui_care_smoke.py
python ui_design_smoke.py
python ui_guidance_smoke.py
python ui_showcase_smoke.py
```

브라우저 검증에는 Playwright와 Chrome 또는 Playwright Chromium이 필요하다. 앱 실행에는 필요하지 않다. 확장 UI 테스트는 격리된 DB와 명시된 합성 병원·검색 결과를 사용하므로 실제 예약이 발생하지 않는다.

전체 UI의 가독성 개편, 변경 전 디자인 체크포인트, 직접 찾아본 참고 사례와 화면 폭별 검증은 [디자인 기록](docs/DESIGN.md)에 정리했다. `ui_design_smoke.py`는 6개 화면 폭의 가로 넘침·텍스트 대비·원문 창·모바일 캘린더를 격리된 합성 자료로 확인한다.

실제 계정 사용량을 소비하는 합성 대화 검증:

```powershell
python live_smoke.py
python live_search_smoke.py
python live_retrieval_smoke.py
python live_demo_smoke.py
python live_calendar_smoke.py
python live_guidance_smoke.py
python live_reading_smoke.py
python live_coaching_smoke.py
```

실제 대화·검색 검증 결과와 한계는 [검증 기록](docs/VALIDATION.md), 4분 시연 흐름은 [데모 안내](docs/DEMO.md), 기획과 당일 개발의 구분은 [개발 기록](docs/DEVELOPMENT.md)에 정리했다.

`live_demo_smoke.py`는 격리된 DB에서 실제 Codex의 생활기록 기억·후속 대화·고문헌 원문 인용·병원 탐색을 이어서 확인하고, 체크인·목표·예약 준비·개인 방문 일정·캘린더 내보내기까지 검증한다. 병원에 접수하거나 예약 확정을 가장하지 않는다.

`live_calendar_smoke.py`는 실제 에이전트와 격리된 DB·명시된 합성 병원을 사용한다. 브라우저의 자체 캘린더에서 8회 연속 요청으로 일정과 예약 기록의 변경, 모호한 입력의 미저장, 상태 표시, 재접속·모바일·대화 분리를 검증한다. 실제 병원 접수는 발생하지 않는다. 캘린더의 사용자 원문·대상 ID·세션 소유권·시간은 서버가 확인하며, 여러 변경과 대화 저장은 한 DB 트랜잭션으로 처리한다.

`live_reading_smoke.py`는 실제 에이전트가 생성한 한국어 해석과 한자 원문의 정확한 위치, 재접속 후 복원을 확인한다. 원문 문자열 검증은 해석의 의미나 임상적 정확성을 보증하지 않는다. 합성 시연의 두 해석도 실제 에이전트가 미리 생성한 결과이며 모델·생성 시각을 `data/showcase.seed.json`에 기록한다.

`python prepare_coaching_demo.py`는 합성 의료진 진단·지침을 저장하고 **실제 에이전트의 첫 질문만** 생성한다. 출력 주소에서 시연자가 답할 수 있으며 실행 시 계정 사용량을 소비한다. `.runtime/coaching-entry.json`에 주소를 저장한다. `live_coaching_smoke.py`는 별도 임시 DB에서 첫 질문 → 환자 답변 → 원문 검증·코칭 → 후속 질문을 확인한다.
