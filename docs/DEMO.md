# 4분 데모

핵심: **한의사 진단·지침 → Hanui가 먼저 확인 질문 → 환자 답변·기록·코칭 → 고문헌 원문·한국어 해석 → 내원 리포트 → 방문 준비**. 현재 ChatGPT 로그인으로 실행하는 OpenAI Codex Luna High가 대화를 연결한다.

## 사전 준비

`python server.py --port 8765`로 실행하고 `python prepare_coaching_demo.py`로 첫 질문 대화를 준비한다. 합성 의료진의 기능성 소화불량 진단·생활 지침을 맥락으로 실제 Luna High가 먼저 질문하며 환자 발언은 아직 없다. 시연자가 답하면 실제 모델이 기록·코칭을 이어간다. 주소는 `.runtime/coaching-entry.json`에 저장한다.

`python seed_showcase.py`의 **합성 데모 A · 한의사 진단에서 먼저 묻는 Hanui**는 별도의 14일 완성 예시다. 첫 질문 → 짧은 환자 답변 → 커피 확인 질문으로 시작하고, 8일 체크인·네 지침·고문헌 인용 두 곳·합성 병원 카드 세 곳·예약 상태·자체 캘린더 7개 일정을 포함한다. **합성 데모 B · 기록 없음·상충**은 누락과 같은 날 서로 다른 커피 발언의 판정 보류를 보여준다. 주소는 `.runtime/showcase-demo.json`에 저장한다. 같은 날 같은 버전 재실행은 주소를 재사용하며 `--new`는 별도 대화를 만든다.

환자·한의사 지침·병원·예약은 합성 예시로 표시하며 기존 개인 대화는 수정하지 않는다. 고문헌 인용은 실제 DB 원문과 위치를 대조한 결과이며, 두 한국어 해석은 실제 Luna High가 미리 생성했다. 초기 시연 대화는 준비한 샘플이며 불러올 때 모델·웹 검색을 실행하지 않는다. 실제 Luna High 대화는 새 대화에서 따로 보여준다. 합성 기록을 모델이 2주간 관찰한 결과라고 소개하지 않는다.

## 0:00~0:35 — 한의사의 지침을 개인 목표로

새 대화 → 생활 기록 → 한의사 지침 입력. 진단·평가와 `취침 23시 전, 찬 음식 줄이기, 커피 1잔 이하, 점심 후 산책 10분`을 저장하면 Hanui가 먼저 확인 질문을 한다. 의료진 입력은 원문·날짜로 확인할 수 있다. 준비한 첫 질문 대화를 사용하면 모델 생성 대기를 줄일 수 있다. 병원의 환자 시스템과 자동 연동된 것으로 소개하지 않는다.

## 0:35~1:15 — 대화에서 지침 대비 기록과 코칭

Hanui의 “어젯밤에는 몇 시쯤 주무셨나요?”에 “어제 새벽 1시에 잤어. 어제 5시간 잤어.”라고 답한다. Luna High의 추출 → 서버의 발언·날짜·수치 대조 → 지침 비교·다음 확인 질문을 보여준다. 기록 원문에서 날짜와 발언을 확인한다. 기록을 말하기 전에는 환자 관찰과 실천율이 생기지 않으며 지침 시작 전 행동은 준수 판정에서 제외한다.

## 1:15~1:55 — 고문헌을 전문 탐색

“황제내경에서 미병과 일상생활 관리에 대해 DB 원문을 찾아줘.”를 입력한다. Luna의 키워드 → SQLite 원문 전체 탐색 → 한국어 해석 → 정확한 인용 대조를 설명한다. 해석을 먼저 읽고 ‘한자 원문·출처’를 펼쳐 문헌명·장절·단락·문자 위치·고정 판본 원문을 확인한다. 총 99건은 현대 요약 42건과 고문헌 원문 57건이다. 고대 기록과 현대 임상 근거를 구분한다.

## 1:55~3:00 — 핵심 장면: 한의사용 내원 전 리포트

목록에서 **합성 데모 A · 지침에서 내원까지**를 열고 내원 리포트를 선택한다. “14일 중 8일 기록, 6일 준수, 실천율 75%, 기록 없음 6일”을 보여준다. 기록 없는 날을 실패나 성공으로 채우지 않는 점을 설명한다. 수면·식사 추이와 환자 불편감의 근거를 눌러 실제 저장된 발언·날짜·본문 위치를 확인하고 원래 대화로 이동한다. 지침 제목은 입력 원문으로 이어진다.

인쇄·PDF 버튼으로 네 지침의 예시가 A4 한 페이지로 정리됨을 보여준다. PDF의 원문 링크도 같은 대화로 돌아온다. 리포트는 검증된 자기보고 자료의 요약이며 임상 효과를 입증한 결과로 소개하지 않는다.

## 3:00~3:40 — 다음 방문 준비

실제 Luna 대화로 돌아가 “강남역 주변 한의원 찾아줘. 이름, 주소, 추천 근거와 전화·예약 링크를 알려줘.”를 입력한다. 간결한 병원 카드와 공개 정보 근거를 보여준다. 검색 지연 시 저장된 직전 결과와 확인 시각을 보여준다.

병원 선택 → 예약 준비 → 자체 캘린더의 희망 방문 시간을 보여준다. 실제 접수는 전화·예약 페이지에서 이루어지며 준비 기록과 사용자의 확정 보고를 구분한다. “내일 오후 3시에 산책 30분 넣어줘”처럼 일정 추가·수정·삭제도 대화로 처리한다. `.ics` 내보내기는 유지한다. 외부 예약 없이 실제 병원 확정을 가장하지 않는다.

## 3:40~4:00 — 구현 근거

단위 테스트 76개, 실제 Luna 선행 질문·환자 답변, 지침 대화 4턴, 자체 캘린더 8턴, 한국어 해석 1턴과 모바일 UI·A4 PDF 검증을 제시한다. 직접 답한 첫 질문 대화와 별도 합성 14일 리포트를 구분한다. 우선 검증할 사용자 과제는 한의사의 내원 전 기록 확인 시간, 환자의 출처 확인 성공률, 기록 누락의 가시성이다. 실제 환자 개선 효과를 이미 얻었다고 주장하지 않는다.
