# 대화와 작업 에이전트

서비스의 메인과 작업 에이전트 모두 `gemma-4-26b-a4b-it`를 사용합니다. 별도 인스턴스지만 같은 로컬 인증 설정과 추론 수준을 사용합니다. 개발용 Codex 서브에이전트와는 다릅니다.

메인은 현재 사용자 메시지만 받아 짧은 답변 또는 작업 위임을 결정합니다. 인사·감사·일반 대화는 메인 호출 한 번으로 끝납니다. DB 검색어 생성, 고문헌 인용, 생활기록 저장을 강제하지 않습니다. 이전 대화를 직접 넘기지 않으므로 문맥이 필요한 모호한 후속 메시지는 확인 질문을 할 수 있습니다.

작업이 필요하면 별도 Gemma 인스턴스가 정해진 역할 프롬프트로 처리합니다.

- `literature`: 최근 대화·한의사 지침을 참고해 검색어를 만들고 DB를 검색합니다. 원문과 국역을 원본 DB와 대조하며, 인용 문자열 및 한국어 해석 필드를 검증합니다.
- `records`: 사용자 발언을 정리하고 생활기록·체크인·목표 초안을 제안합니다. DB·웹 검색과 고문헌 인용을 하지 않습니다.
- `calendar`: 현재 대화의 일정·예약 준비 자료를 보고 변경 요청을 구조화합니다. DB·웹 검색과 고문헌 인용을 하지 않습니다.
- `web`: 최신 공개 정보·장소에 대해 검색 필요 여부를 판단하고 기존 제한된 브라우저 검색을 사용합니다. 고문헌 검색을 강제하지 않습니다.

메인은 작업 에이전트의 결과를 받아 사용자에게 설명합니다. 원문 인용·위치는 에이전트의 검증된 결과를 그대로 표시하며 메인이 다시 생성하지 않습니다. 일반 작업은 메인 판단 → 작업 에이전트 → 메인 설명의 세 번 호출이고, 문헌 작업은 검색어 생성 호출이 추가되어 통상 네 번 호출합니다. 실제 도구 필요에 따라 추가 호출이 생길 수 있습니다.

일정 변경과 환자 기록 저장은 서버의 기존 검증 및 트랜잭션을 통해 실행합니다. 작업 프롬프트가 원래 사용자 발언을 대신해 쓰기를 허가하지 않습니다. 취소·인용 오류·메인 설명 생성 실패 시 작업 결과를 저장하지 않습니다. 사용자 확인이 필요한 체크인·목표는 기존 초안 흐름을 유지합니다. 한 번의 위임은 한 역할로 제한합니다.

웹 검색 실패·모델 한도는 기존 오류 처리로 표시합니다. 별도 작업 에이전트의 호출도 같은 API 할당량을 사용합니다. 예약은 로컬 방문 준비이며 외부 병원의 확정을 대신하지 않습니다.
