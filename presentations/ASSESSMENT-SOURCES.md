# 발표 근거와 심사 기준 대응

2026-10-09 확인. 공식 [Luma 행사 공지](https://luma.com/f7h7onav?tk=q0Qsmw)와 연결된 [서울 해커톤 상세 안내](https://codex-community-korea.skysplit.chatgpt.site/hackathon/seoul-2026-10?utm_source=luma)를 기준으로 작성했다. 1차는 발표·데모 합계 **4분, 질의응답 없음**이다. 결선은 발표·데모·질의응답을 합쳐 **최대 10분**이므로 이 덱은 발표 8분과 질의응답 2분으로 짰다. PDF가 필수 제출 항목이며, 상세 파일명과 업로드 위치는 운영진의 별도 안내를 따른다. 세부 배점은 공지에 없다.

## 선제 대화·자료 권리·확장 범위

- **선제 대화**: 한의사가 진단·평가와 생활 지침을 저장하면 Hanui가 **앱 안에서 먼저 질문**한다. 환자 답변을 받은 뒤 다음 상태를 묻고 다음 방문까지 기록을 연결한다. 외부 푸시 알림이나 문자 발송은 구현하지 않았다.
- **한의학을 택한 이유**: 이 프로젝트에 수록한 고문헌의 **원전 자체**는 저작권이 만료된 역사 자료다. 현대 번역·편집본에는 별도 권리가 생길 수 있으며, 이용한 중국어 Wikisource 전사본의 기여는 CC BY-SA 4.0·GFDL 조건에 따라 취급한다. 이는 모든 한의학 자료가 자유 이용 가능하다는 뜻이 아니다. 근거: [중국어 Wikisource 저작권 안내](https://zh.wikisource.org/zh-hant/Wikisource%3ACopyright), [Creative Commons의 공공영역과 새 창작 부분 설명](https://creativecommons.org/course/cc-cert-edu/unit-2-copyright-law/2-3-the-public-domain/), 저장소 [`docs/CLASSICAL_SOURCES.md`](../docs/CLASSICAL_SOURCES.md)의 고정 판본·기여자 표시·라이선스.
- **확장 계획**: 의사 지침 → 앱 내 선제 대화 → 환자 생활 기록 → 근거 확인 → 다음 내원 리포트라는 공통 구조를 한의학 밖에도 적용하려 한다. 다른 의료 분야에는 그 분야의 검증된 자료와 전문가 지침을 새로 적용·검증해야 한다. 현재 프로토타입이 현대의학 전반을 지원한다는 뜻은 아니다.

## 수치·화면·범위의 출처

- **42 + 57 = 99**: 저장소 [`README.md`](../README.md), 고문헌 출처 목록 [`docs/CLASSICAL_SOURCES.md`](../docs/CLASSICAL_SOURCES.md), 시드 데이터 `data/knowledge.seed.json`과 `data/classics.seed.json`. 고문헌은 수록된 발췌 원문이며 전체 원전이 아니다.
- **6/8=75%, 기록 없음 6일**: [`docs/GUIDANCE.md`](../docs/GUIDANCE.md)와 합성 데모 [`data/showcase.seed.json`](../data/showcase.seed.json). 임상 효능 또는 실제 환자 성과가 아니다.
- **80개 테스트, 실제 에이전트 연결**: 2026-10-09 재실행 결과와 [`docs/VALIDATION.md`](../docs/VALIDATION.md). 신규 [`live_coaching_smoke.py`](../live_coaching_smoke.py)는 에이전트가 먼저 의료진 지침 맥락의 질문을 만들고, 환자 답변 후 날짜·수치 확인과 다음 질문을 반환하는 흐름을 확인했다. 첫 질문과 후속 답변 모두 고문헌 원문 인용, 한국어 해석, 문자 offset 대조를 통과했다. 26.3초는 단일 실행이며 지연 시간 보장이 아니다. 화면용 합성 시연은 모델·실제 병원 접수를 실행하지 않는다.
- **화면 캡처와 발표용 예시**: `presentations/assets/`의 `showcase-*`는 격리된 합성 환자·한의사 진단·병원·일정 예시. 4분 4장과 10분 7장의 동일한 예/아니오 화면은 발표용 개념 예시다. 앱 안에서 먼저 묻는 대화는 구현됐지만 버튼 입력은 아직 기획 화면이다. 합성 첫 질문은 시연 fixture이고 실제 계정의 에이전트 생성 첫 질문 검증과 구분한다.
- **서비스 범위**: [`README.md`](../README.md), [`docs/GUIDANCE.md`](../docs/GUIDANCE.md). 의료 진단·체질 판정·처방·약재 구매·실제 병원 예약 접수·지도 경로는 제공하지 않는다. 예약 링크는 외부 페이지로 이동한다. 인용 검증은 문자 일치와 위치 확인이며 해석의 임상적 타당성 검증이 아니다.
- **개발 이력**: [`docs/DEVELOPMENT.md`](../docs/DEVELOPMENT.md). 사전 계획 자료와 당일 신규 구현·확장·검증을 분리해 설명한다. 발표의 시장성은 계획 또는 가설이며 실제 시장 검증 수치가 없다.

## 파일 안내

`Hanui-Relay-4min.pdf`는 1차 발표용 8장, `Hanui-Relay-10min.pdf`는 결선용 14장이다. 같은 이름의 PPTX는 텍스트·도형을 PowerPoint에서 편집할 수 있다. `*-script.md`는 슬라이드별 시간과 대본이다. `build.py`는 로컬 합성 화면으로 PPTX를 다시 만드는 스크립트다. 네트워크나 앱 연결이 어려워도 PDF로 발표할 수 있다.
