# 개인 건강 관리 구현

## 사용 흐름

1. 사이드바 아래 **시스템 지침**에서 에이전트 성격과 **개인 건강 프로필**을 각각 작성한다.
2. 대화 위 **관리 시작**을 펼쳐 불편한 점, 시작 시점, 목표를 입력한다. 에이전트가 첫 확인 질문을 생성한다.
3. **오늘의 관리**에서 목표 실천에 예/아니요로 답하거나 대화로 생활을 기록한다.
4. **주간 요약**에서 기록 여부, 목표 자기보고, 지침 판정, 수면·카페인 추이와 실제 발언을 확인한다.
5. **리포트로 가져오기**는 기존 글 뒤에 날짜별 근거를 추가한다. 직접 수정하고 저장하거나 기존 에이전트 정리 기능을 사용할 수 있다.
6. 병원에서 예약 확정을 받았다고 기록한 일정은 방문 날짜부터 **방문 후 지침 입력**으로 연결한다. 사용자가 전달한 지침임을 표시하며 의료진이 인증한 지침으로 취급하지 않는다.

## 프로필 메모리

프로필은 계정 저장소의 SQLite에 최대 30,000자 텍스트로 저장한다. 시스템 프롬프트와 분리한다. 줄 단위·최대 600자 단락을 FTS5로 색인하고, 질문의 키워드·한국어 표현과 관련 있는 최대 5개 단락을 검색한다. 짧은 후속 질문은 최근 사용자 발언을 보조 검색어로 사용한다. 단락에는 원문 위치와 프로필 개정 식별자를 포함한다.

메인 대화와 작업 에이전트에는 검색된 단락만 **사용자가 작성한 데이터**로 전달한다. 프로필 안의 명령을 실행하거나 추측으로 프로필을 변경하지 않는다. 프로필 수정은 다음 요청부터 적용하며 삭제하면 색인도 비운다. 대화를 삭제해도 개인 프로필은 유지한다. 별도 임베딩 모델이나 추가 AI 추론을 검색 단계에 호출하지 않는다.

## 기록과 주간 요약

요약은 현재 사용자 저장소의 여러 대화를 대상으로 한다. 다른 로그인 사용자의 저장소는 읽지 않는다. 발언에서 검증한 관찰, 직접 작성한 체크인, 예/아니요 목표 응답을 날짜별로 표시한다. 관리 시작의 자기소개를 실제 생활 측정으로 세지 않는다.

- 기록 없는 날은 **기록 없음**으로 표시한다.
- **목표 자기보고**와 관찰 수치로 판정한 **한의사 지침 실천율**을 분리한다.
- 예/아니요 응답은 같은 목표·날짜에서 최신 응답으로 수정할 수 있다. 과거 대화 원문은 남긴다.
- 평균은 날짜별로 일치하는 측정값만 사용하며, 상충하는 값은 제외하고 상충 여부를 표시한다. 0도 유효한 측정이다.
- 고문헌과 현대 공개 자료는 자료 창에서 구분한다. 원문 일치 검증이 임상적 타당성이나 전문가 검토를 대신하지 않는다. 실제 전문가 검토는 별도 운영 작업이다.

## 알림

**알림**에서 시간을 정하고 브라우저 알림을 켠다. 사용자 동작으로 브라우저 권한과 Web Push 구독을 등록한다. 서버 스케줄러가 30초마다 확인하므로 앱 탭을 닫아도 알림을 전송할 수 있다. 로컬 서버가 꺼져 있으면 전송하지 못한다. 브라우저·운영체제의 백그라운드 알림 설정에 따라 수신 가능 여부가 달라진다.

예약 준비는 일정 알림으로 확정하지 않는다. 개인 일정·사용자 확인된 방문은 시작 30분 전부터 확인한다. 매일 관리 알림은 선택한 시각부터 30분 내 전송한다. 구독별 전송 성공을 저장해 중복을 막고, 실패는 최대 3번 시도한다. 만료된 구독은 정리한다. 푸시 본문에는 증상·약물·지침 원문을 포함하지 않는다. 기존 앱 내 알림 문구 생성은 유지한다.

VAPID 비밀키, 구독 주소와 로그인 자료는 `.runtime/`에만 저장한다. 서버 운영자가 공개 서비스의 연락처를 설정하려면 `HANUI_PUSH_CONTACT`에 실제 HTTPS URL 또는 mailto URI를 지정한다.

## Google 연결 준비 — 현재는 로컬 사용

사용자 요청에 따라 Google 계정 연결 활성화는 보류한다. OAuth 클라이언트 ID가 없으면 기존 로컬 사용자 모드가 동작하고 로그인 버튼을 노출하지 않는다. 준비된 코드는 Google 로그인, 로그아웃, 계정별 대화·프로필·기록·일정·리포트 저장소 분리다. 기존 로컬 데이터는 로그인 계정에 자동 이전하지 않는다.

나중에 활성화하려면:

```powershell
python -m pip install -r requirements.txt
$env:HANUI_GOOGLE_CLIENT_ID = '<웹 OAuth 클라이언트 ID>'
python server.py --port 8765
```

환경변수 대신 `.runtime/google-login.json`의 `client_id`를 사용할 수 있다. Google 콘솔의 승인된 JavaScript 원본에 `http://localhost:8765`, `http://127.0.0.1:8765`를 등록한다. GIS에서 받은 ID 토큰은 google-auth로 서명·대상·발급자·만료를 검증하고, 로그인 nonce는 한 번만 사용한다. 계정 식별은 이메일 대신 `sub`로 한다. [Google 인증 검증 안내](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)

현재 HTTP 서버는 loopback 전용이다. Google 로그인 준비가 공개 인터넷 배포 완료를 의미하지 않는다. 실제 OAuth 로그인은 클라이언트 ID가 준비된 뒤 브라우저에서 검증해야 한다.

## 디자인과 검증

추가 카드·프로필 영역의 CSS 초안은 `gemini-3.8-flash`, thinking `HIGH`로 생성했다. 생성된 CSS의 잘못된 선택자와 컴포넌트 배치, 모바일·인쇄 범위를 검토하고 수정했다. 기존 사이드바와 대화 화면 구조는 유지한다.

```powershell
python -m unittest discover -s tests -q
python ui_health_platform_smoke.py
python ui_shell_smoke.py
python ui_cancel_smoke.py
python ui_report_document_smoke.py
```

자동 테스트는 합성 자료와 격리 저장소를 사용한다. Google 토큰 검증 외부 호출과 실제 푸시 서비스 전송은 단위 테스트에서 모의 처리하며, 실제 사용자 Google 로그인 및 푸시 수신을 통과한 것으로 표시하지 않는다.
