## 읽는 순서와 시각적 우선순위

기본 배경은 옅은 회색, 콘텐츠는 흰색, 본문은 짙은 중립색이다. 짙은 초록색은 현재 메뉴·핵심 행동·원문 인용·선택한 날짜에 사용한다. 큰 그림자와 그라데이션을 제거하고 일정한 간격, 구분선, 8~16px 모서리로 영역을 나눈다. 이전 스타일의 중첩 덮어쓰기는 읽기 쉬운 단일 CSS 체계로 정리했다.

- 대화: 16px 답변 본문 → 16~17px 원문 인용 → 12~13px 인용 위치 → 전체 자료 열기. 원문은 초록색 왼쪽 선과 별도 배경을 갖는다. 출처 개수는 DB 전체 개수 대신 이번 답변에 실제 사용한 자료 수다.
- 원문 창: 제목·출처·판본/장절 위치 → DB에 수록된 원문 → 독해 안내 → 적용 범위 → 원문 링크. 원문과 편집한 독해를 명시적으로 구분한다. 없는 위치·독해는 빈 상자를 표시하지 않는다.
- 생활 관리: 큰 요약 수치 → 오늘 체크인과 목표 → 기록 흐름. 수치를 읽는 글자와 폼 라벨을 키우고 저장 버튼을 강조한다.
- DB: 검색 입력 → 자료 종류 → 결과 카드 → 원문 확인. 고문헌 원문만 볼 수 있는 필터를 추가했다. 기존 서버의 `classical` 필터를 연결하며 자료 자체를 변경하지 않는다.
- 병원: 이름 → 주소 → 추천 근거 → 예약 준비. 전화·외부 예약 링크·방문 일정 저장은 유지하고, 공개 자료는 펼쳐 읽는다.
- 캘린더: Luna 요청 입력 → 월별 날짜 → 선택한 날짜의 일정 → 전체 기록. 개인 일정·접수 전 예약 준비·병원 확정은 범례와 글자로 구분한다. 모바일 날짜 칸은 읽기 어려운 작은 제목 대신 건수를 표시하며 아래 목록에서 시간·제목·주소·상태를 읽는다.
- 사이드바: 생활기록과 이번 답변 자료를 독립된 보조 패널로 묶는다. 모바일은 닫기·배경 클릭·Escape로 닫는 오버레이를 사용한다.

주요 버튼과 입력은 대체로 44px 이상이며, 키보드 포커스는 짙은 초록색 테두리로 표시한다. 모바일 대화 입력은 16px이다. 메뉴의 활성 상태 전환은 글자 대비를 유지하도록 배경색을 즉시 바꾼다. 움직임 감소 설정도 따른다.

## 검증

```powershell
python -m unittest discover -s tests -q
python ui_smoke.py
python ui_care_smoke.py
python ui_design_smoke.py
```

- 단위 테스트 49개 통과.
- 기본 대화와 확장 기능의 Chrome 브라우저 테스트 통과. 기억·인용·재접속·생활기록·예약 상태·캘린더·ICS·여러 대화·사이드바를 확인했다.
- 디자인 검증은 격리된 SQLite와 명시된 합성 병원·일정만 사용한다. 모델이나 실제 예약을 실행하지 않는다.
- 320/360/390/768/1024/1440px의 대화·생활·DB·캘린더, 사이드바, 원문 창에서 가로 넘침을 확인했다.
- 실제 계산된 글자색과 불투명 배경색의 대비를 검사했다. 일반 글자는 4.5:1, 큰 글자는 3:1 기준을 통과했다. 이는 해당 화면의 텍스트 검사이며 전체 접근성 적합 인증은 아니다.
- 한 날짜에 개인 일정 3개와 예약 준비 1개를 배치해 날짜 칸·모바일 건수·전체 목록을 확인했다.
- 캡처는 `.runtime/screenshots/redesign-*`, 요약은 `.runtime/design-check.json`에 남긴다.

지도·경로·이동 시간·Google Calendar 기능을 되살리지 않았다. 자연어 일정/예약 처리와 DB 검색 모델·계정 설정은 유지한다.
